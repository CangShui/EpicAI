# EpicAI 项目开发任务书

## 1. 项目名称

**EpicAI — OpenAI Compatible AI Endpoint Simulator**

项目定位：面向 AI 客户端、Agent、网关、中间件、SDK、重试组件和前端聊天程序的 **OpenAI 兼容接口模拟器 / 故障注入平台 / 人工会话接管平台**。

EpicAI 本身不需要运行真实大语言模型。

默认提供一个模型：

`epic-alpha`

该模型的核心行为不是推理，而是：

> 客户端发送什么，服务器就持续不断地重复返回什么，直到客户端主动断开、管理员结束会话，或管理员注入指定错误。

---

# 2. 项目目标

EpicAI 需要解决以下测试需求：

1. 测试客户端是否兼容 OpenAI 风格 API。
2. 测试客户端是否能正确处理长时间 Streaming。
3. 测试客户端面对永不自然结束的模型时的行为。
4. 测试客户端主动取消请求的行为。
5. 测试客户端超时机制。
6. 测试客户端 Token/内容无限增长情况下的处理。
7. 测试客户端收到 400、401、403、404、408、409、413、422、429、500、502、503、504 等错误时的行为。
8. 测试客户端收到自定义错误代码、自定义 JSON、自定义错误信息时的行为。
9. 测试客户端遇到流式响应中途报错时的行为。
10. 测试客户端处理文字、图片、文件以及混合多模态内容的能力。
11. 允许后台管理员随时人工接管某次 AI 对话。
12. 允许管理员模拟模型回复、延迟、卡死、断流、异常结束等各种情况。
13. 允许动态创建、删除、启用、禁用模型。
14. 所有行为可以通过 Web 管理后台进行操作。

---

# 3. 核心设计原则

## 3.1 不运行真实 AI

EpicAI 不调用任何真正的大语言模型。

所有输出由以下模块产生：

* Echo Engine
* Scenario Engine
* Manual Takeover Engine
* Fault Injection Engine

---

## 3.2 OpenAI 协议适配层

内部必须建立统一的 Canonical Message/Event Model。

不同接口首先解析成统一内部结构：

```text
OpenAI Chat Completions
        ↓
OpenAI Responses
        ↓
Legacy Completions
        ↓
Files / multimodal input
        ↓
Canonical Conversation
        ↓
Echo / Manual / Fault Engine
        ↓
Protocol Adapter
        ↓
对应 OpenAI 风格响应
```

禁止针对每个接口分别实现一套完全独立的会话逻辑。

# 5. Chat Completions API

必须实现：

```http
POST /v1/chat/completions
```

兼容至少以下字段：

```json
{
  "model": "epic-alpha",
  "messages": [],
  "stream": true,
  "temperature": 1,
  "top_p": 1,
  "max_tokens": 1000,
  "max_completion_tokens": 1000,
  "stop": null,
  "n": 1,
  "user": "test"
}
```

对于不影响 EpicAI 行为的 OpenAI 参数：

原则上应：

> 接受并忽略，而不是因为未使用这些参数而报错。

后台日志需要记录原始 request body。

# 9. 流式响应

`epic-alpha` 的标准无限模式必须优先通过 Streaming 实现。

Chat Completions：

```text
Content-Type: text/event-stream
```

服务器持续返回合法 SSE Chunk。

示意：

```text
data: {"id":"chatcmpl_xxx","object":"chat.completion.chunk",...}

data: {"id":"chatcmpl_xxx","object":"chat.completion.chunk",...}

data: {"id":"chatcmpl_xxx","object":"chat.completion.chunk",...}
```

正常 Infinite Echo 模式：

**永远不要主动发送 `[DONE]`。**

只有出现以下事件才结束：

* 客户端断开
* 管理员 Stop
* 管理员 Inject Error
* 会话被系统策略终止
* 服务器关闭

---

# 10. 非流式请求

OpenAI 标准非流式响应无法合法表达“无限个完整响应”。

因此系统必须区分：

### Strict Compatibility Mode

当：

```json
"stream": false
```

时返回一次完整 Echo。

这是默认行为。

### Chaos Infinite Non-stream Mode

管理员可启用：

```text
Hold Connection Forever
```

此模式故意保持 HTTP 请求不完成，用于测试客户端：

* timeout
* abort
* connection handling

必须在管理后台明显标记：

```text
NON-STANDARD / CHAOS MODE
```

防止将其误认为标准 OpenAI 行为。

# 14. 图片回显

需要提供两种兼容模式。

## Strict OpenAI Mode

在当前协议无法直接合法返回原始 image input 类型时：

服务器将图片保存到 EpicAI Asset Store，并产生：

```text
/epic-assets/{asset_id}
```

输出中通过当前协议允许的内容形式返回图片 URL。

对于支持 Markdown 的客户端，例如：

```markdown
![epic echo](https://server/epic-assets/xxx)
```

客户端因此可以实际显示原图片。

---

## Relaxed Multimodal Mirror Mode

提供可选：

```text
Relaxed OpenAI Compatible
```

允许按照输入 content part 的结构直接 Mirror：

```json
[
  {
    "type": "image_url",
    "image_url": {
      "url": "..."
    }
  }
]
```

该模式用于测试各种“OpenAI-compatible”第三方客户端。

后台必须明确标记该模式可能包含非官方扩展。

# 15. 文件回显

文件不得每轮重新上传。

第一次请求：

```text
文件 → Asset/File Store
```

* file_id
* URL
* filename
* MIME
* metadata

避免无限复制实际文件造成磁盘爆炸。

管理员可以配置：

```text
repeat_file_reference
repeat_download_url
repeat_metadata
```

# 19. 人工接管

这是 EpicAI 的核心功能之一。

会话页面提供：

```text
TAKE OVER
```

管理员点击后：

```text
ECHOING → MANUAL
```

Echo Engine 立即暂停。

客户端连接保持不变。

管理员出现输入框：

```text
Type a manual assistant response...
```

管理员输入：

```text
我是管理员，现在由人工接管。
```

客户端应立即收到：

```text
我是管理员，现在由人工接管。
```

# 27. OpenAI 风格错误

默认错误模板：

```json
{
  "error": {
    "message": "Rate limit exceeded",
    "type": "rate_limit_error",
    "param": null,
    "code": "rate_limit_exceeded"
  }
}
```

所有字段允许修改。

例如管理员输入：

```text
HTTP Status:
429

Code:
6004

Type:
quota_exceeded

Message:
您的使用量已超出频率限制
```

可以返回：

```json
{
  "error": {
    "message": "您的使用量已超出频率限制",
    "type": "quota_exceeded",
    "param": null,
    "code": 6004
  }
}
```

---

# 28. Raw Error

管理员允许完全自定义：

```json
{
  "code": 429,
  "message": "upstream 429",
  "detail": {
    "code": 6004,
    "msg": "您的使用量已超出频率限制"
  }
}
```

选择：

```text
RAW RESPONSE
```

以后服务器必须原样返回。

---

# 29. 流中错误

EpicAI 必须支持：

```text
正常输出 20 次
↓
管理员 Inject Error
↓
流异常结束
```

至少支持：

### Mode A

直接关闭连接。

### Mode B

在 SSE 中发送 Error Event。

### Mode C

最后发送 HTTP/协议可表达的错误。

### Mode D

发送 malformed chunk 后关闭。

EpicAI 必须实现完整的 **Token Rate Limiting / Throughput Simulation** 系统。

# 59. Token/s 定义

EpicAI 所有输出速率统一使用：

```text
token/s
```

即：

```text
Output Tokens Per Second
```

不得使用：

```text
chunks/s
messages/s
characters/s
```

代替。

内部必须存在统一 Token Counter。

建议默认采用与 OpenAI 常用模型兼容的 tokenizer 实现。

如果无法精确获得目标模型 tokenizer，则 EpicAI 自己规定一个固定 Canonical Tokenizer，并在后台明确显示：

```text
Token accounting is based on EpicAI Canonical Tokenizer.
```

这样同一次测试在不同时间必须得到相同 token 数。

---

# 60. 无限制模式

EpicAI 必须支持：

```text
Rate Limit:
Unlimited
```

Unlimited 意味着：

> Echo Engine 不主动等待，数据一旦生成立即向客户端输出，由 CPU、运行时、网络栈、TCP、TLS、HTTP/SSE、客户端读取速度和系统背压共同决定最终速度。

代码中不得通过：

```text
sleep(0)
sleep(1ms)
固定 interval
```

人为限制 Unlimited 模式。

---

# 61. 无间隔模式不存在固定通用 token/s

必须在项目文档明确说明：

```text
Unlimited ≠ 一个固定 token/s 数字
```

实际最大速率取决于：

```text
CPU
Runtime
JSON serialization
SSE framing
TLS
Network bandwidth
TCP backpressure
Chunk size
Tokenizer
Client receive speed
```

理论网络上限可估算为：

```text
tokens_per_second ≈
available_bytes_per_second /
average_wire_bytes_per_token
```

例如纯文本极端理想情况：

```text
1 Gbps
≈ 125,000,000 Byte/s

假设：
4 Byte/token

则：
125,000,000 / 4
≈ 31,250,000 token/s
```

但该数字未包含：

```text
SSE
JSON
HTTP
TCP
TLS
字段结构
chunk framing
```

因此不能作为部署环境真实最大值。

# 64. 全局 Token Rate Limit

必须支持：

```text
Global Output Rate Limit
```

例如：

```text
Global:
1000 token/s
```

表示：

> EpicAI 所有当前会话合计，每秒最多发送约 1000 个 output token。

例如同时存在：

```text
Session A
Session B
Session C
Session D
```

总输出不得长期超过：

```text
1000 token/s
```

允许短时间出现非常小的调度误差，但长期平均必须符合限制。

---

# 65. 单会话 Token Rate Limit

每个 Session 必须可以独立设置：

```text
Session Rate Limit
```

例如：

```text
Session A:
10 token/s

Session B:
100 token/s

Session C:
Unlimited
```

管理员可以在会话运行过程中实时修改。

例如：

```text
100 token/s
↓
1 token/s
```

客户端连接不得因此断开。

输出应该立即逐渐降低到约：

```text
1 token/s
```

反过来：

```text
1
↓
1000 token/s
```

也无需重新建立连接。

# 66. Effective Rate

一个会话实际输出速度必须满足：

```text
Effective Session Rate
=
min(
    Session Rate Limit,
    Global Scheduler Allocation,
    Physical/Runtime Throughput
)
```

如果以后加入 Model Rate Limit，则：

```text
Effective Session Rate
=
min(
    Session Limit,
    Model Limit,
    Global Allocation,
    Physical Throughput
)
```

# 67. 全局限速的公平调度

如果：

```text
Global Limit = 1000 token/s
```

同时有：

```text
10 个 Unlimited Session
```

默认应近似公平分配：

```text
Session 1 ≈ 100 token/s
Session 2 ≈ 100 token/s
...
Session 10 ≈ 100 token/s
```

推荐实现：

```text
Token Bucket
+
Round Robin / Fair Queue
```

禁止第一个建立的 Session 永久抢占所有额度。

# 68. 不同 Session Limit 下的调度

例如：




# 71. Chunk 与 Token Rate 解耦

必须区分：

```text
Token Rate
```

和：

```text
Chunk Size
```

例如：

```text
100 token/s
chunk_size = 20 tokens
```

可以表现为：

```text
约每 200ms
发送一个 20-token chunk
```

而：

```text
100 token/s
chunk_size = 1
```

则约：

```text
每 10ms
发送一个 token
```

两者平均 Token Rate 相同。

后台必须可以调整：

```text
Chunk Size
```

至少：

```text
1
4
8
16
32
64
128
256
Auto
```

# 73. 并发超限行为

后台允许选择：

```text
Reject
Queue
Hang
Custom Error
```

## Reject

立即：

```text
HTTP 429
```

默认：

```json
{
  "error": {
    "message": "EpicAI concurrent session limit exceeded",
    "type": "rate_limit_error",
    "code": "concurrency_limit_exceeded"
  }
}
```

## Queue

请求进入：

```text
WAITING_FOR_SLOT
```

直到有 Session 退出。

## Hang

故意保持连接但不给任何响应。

用于测试客户端超时。

## Custom Error

管理员自己指定：

```text
HTTP Status
Error Code
Error Message
Raw Body
```
